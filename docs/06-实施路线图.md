# 06 实施路线图

> 文档定位：回答"先做什么、后做什么、怎么算成功"。

## 1. 阶段规划

| 阶段 | 目标 | 关键交付物 | 预估时长 |
| --- | --- | --- | --- |
| M0 调研与标准 | 摸清试点馆现状，定标准 | 调研报告、元数据规范 v1、采集规范 v1 | 1–2 月 |
| M1 MVP 单馆试点 | 跑通"登记—溯源—验证"闭环 | 联盟链（4 节点）、登记/溯源合约、管理后台、验证页 | 2–3 月 |
| M2 采集流水线与分级展示 | 打通真实采集，开放公众查询 | 采集工具链、L0-L3 分级存储、公众查询端、审计 | 2–3 月 |
| M3 联盟扩展与互认 | 多馆接入，凭证互认 | DID/VC 体系、跨馆互认流程、链浏览器 | 3–6 月 |
| M4 授权与生态 | 数字资源授权与（可选）数字藏品 | 授权平台、收益分配、开放 API；数字藏品单独论证 | 持续 |

## 2. MVP 范围（M1）

**包含**
- 联盟链 4 节点（主管部门、试点馆、公证机构、平台方）；
- TwinRegistry + ProvenanceLog 合约；
- 管理后台：孪生登记、状态管理、事件录入；
- 公众验证页：上传文件 → 哈希比对 → 结论；
- 溯源查询页：按文物查看事件时间线。

**不包含**
- 数字藏品、DID/VC 完整体系、图库检索、开放 API、跨链锚定（进入 M2+）。

## 4. 成本估算（粗，供立项参考）

- M1 阶段以人力成本为主：4–6 人 × 2–3 个月；
- 基础设施：4 个链节点（可复用机构机房或云主机，单节点 4C8G 即可）；
- 存储：按试点规模估算，L0/L1 每件 5–50GB，规划 10–50TB 起步。

## 5. 验收标准（可测）

| 场景 | 验收标准 |
| --- | --- |
| 登记 | 提交孪生后 10 秒内可在链浏览器查到登记记录 |
| 验证 | 对任意登记文件做 1 字节篡改，验证页必须判定"被篡改" |
| 溯源 | 任意修复事件可在 5 秒内完成链上核验 |
| 容错 | 停掉 1 个链节点，业务不受影响 |
| 安全 | 未授权角色无法写入登记与事件合约 |

## 6. 度量指标

| 指标 | 目标（M3 时） |
| --- | --- |
| 登记文物数 | ≥ 500 件 |
| 溯源事件数 | ≥ 5000 条 |
| 接入机构数 | ≥ 5 家 |
| 公众验证查询 | 月均 ≥ 1 万次 |
| 数据完整率 | 100%（抽查） |
