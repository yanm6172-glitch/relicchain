# 04 系统架构与技术选型

> 文档定位：回答"系统分几层、每层用什么技术、怎么部署"。

## 1. 总体架构

```
┌────────────────────────────────────────────────────────────┐
│ 应用层：管理后台 · 公众查询端 · 数字展厅 · 开放 API           │
├────────────────────────────────────────────────────────────┤
│ 服务层：孪生管理 · 登记服务 · 溯源服务 · 授权服务 ·          │
│         审计服务 · DID 服务 · 文件服务                       │
├────────────────────────────────────────────────────────────┤
│ 链适配层：统一接口（登记/查询/事件/订阅）——隔离具体链实现     │
├───────────────────────────┬────────────────────────────────┤
│ 联盟链节点群（FISCO BCOS） │ 数据层：对象存储 · 关系库 ·     │
│ 共识：PBFT                │        图库(溯源) · 搜索引擎    │
└───────────────────────────┴────────────────────────────────┘
采集层（线下/工具）：三维扫描 · 摄影测量 · 光谱检测 · 修复记录
```

## 2. 分层职责

| 层 | 职责 | 说明 |
| --- | --- | --- |
| 采集层 | 产生 L0/L1 原始数据 | 复用馆方现有设备与流程，平台提供采集规范与工具 |
| 数据层 | 文件存储与业务数据 | 大文件存对象存储；结构化数据存关系库；溯源关系存图库 |
| 服务层 | 业务逻辑 | 校验、签名编排、工作流、对外接口 |
| 链适配层 | 屏蔽链差异 | 统一合约调用/查询/事件订阅接口，未来可换链 |
| 应用层 | 用户界面 | 管理后台（机构）、公众端（H5/小程序）、数字展厅 |

## 3. 技术栈候选

| 模块 | 首选 | 备选 | 说明 |
| --- | --- | --- | --- |
| 后端服务 | Go | Java(Spring Boot) | 高并发下 Go 资源占用低；团队熟悉 Java 则用 Java |
| 前端 | Vue 3 + TypeScript | React | 管理后台与公众端 |
| 数据库 | PostgreSQL | MySQL | JSON 支持好，适合半结构化元数据 |
| 图库 | Neo4j | NebulaGraph | 溯源关系与文物关联检索 |
| 对象存储 | MinIO | 云 OSS | 私有化部署优先 |
| 搜索引擎 | Elasticsearch | OpenSearch | 元数据全文检索 |
| 链 SDK | FISCO BCOS Java/Go SDK | 长安链 SDK | 与链交互 |
| 密钥管理 | KMS / HSM | 自建 Vault | 机构私钥托管 |
| 网关 | Nginx / Kong | | TLS 终结与限流 |

## 4. 关键交互时序

### 4.1 登记

```
馆藏单位 → 管理后台提交孪生 → 文件服务计算哈希/Merkle 根
→ 登记服务构建交易 → KMS 签名 → 链上 registerTwin → 回执 → 状态落库
```

### 4.2 溯源查询

```
公众/机构 → 查询服务 → 链上 queryEvents + 链下证据索引
→ 返回事件列表 + 证据文件（按分级权限）→ 前端可离线哈希校验
```

## 5. API 设计原则

- 对外 RESTful + 签名认证（防篡改、防重放）；
- 查询类接口只读，写入类接口必须机构签名；
- 开放平台提供 SDK（计算哈希、验签、查询），降低接入门槛。

## 6. 安全设计

| 层面 | 措施 |
| --- | --- |
| 传输 | 全链路 TLS |
| 存储 | L0/L1 数据 SM4 加密，密钥托管 KMS |
| 身份 | 机构 DID + 数字证书，关键操作多签 |
| 访问控制 | RBAC + ABAC（按数据分级） |
| 审计 | 访问日志上链（AuditLog 合约） |
| 合约 | 上线前第三方审计 + 治理合约预留升级机制 |

## 7. 部署拓扑

- **链节点**：4–7 个机构各运行 1 节点，机房分开；
- **业务集群**：平台方集中部署（K8s），机构通过 Web/SDK 接入；
- **存储**：对象存储主备 + 异地备份；链上只存哈希，数据恢复只影响可用性、不影响完整性。

## 8. 性能与容量估算（经验值，需按试点校正）

| 指标 | 量级 | 说明 |
| --- | --- | --- |
| 单件文物孪生数据量 | 5–50 GB（L0/L1 合计） | 高精度扫描体积大 |
| 写入频率 | 每馆每日几十至几百条事件 | 低频高价值 |
| 链 TPS 需求 | < 10 | 联盟链轻松满足 |
| 查询并发 | 公众端高峰几百 QPS | 靠链下索引缓存，不直接压链 |

**结论**：瓶颈在存储与采集，不在链性能。

## 9. 可观测与运维

- 链监控：节点状态、区块高度、共识健康（WeBASE 等工具）；
- 业务监控：接口延迟、错误率、任务队列；
- 链浏览器：面向公众的可信查询页面（读链上登记与事件）。
