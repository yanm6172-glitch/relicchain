# 17 APP 打包与部署指南（一条龙：技术闭环 × 商业闭环）

> 目标：从"双击网页"升级为"手机上的真 APP + 扫码验证"，实现技术与商业双闭环。

## 1. 技术闭环（一张图）

```
文物数字化(采集/建模)
      ↓
平台登记(哈希+元数据上链，真挖矿)
      ↓
存证凭证(打印/下载，含凭证编号 RC:馆藏编号:区块号)
      ↓
生成真码(草料/微信，内容=扫码串)  ← 本机离线环境由用户自行生成
      ↓
游客手机 APP「扫一扫」→ 相机识别 → 解析编号 → 链上查证 → 结论
      ↓
闭环：登记 → 凭证 → 扫码 → 核验 → 信任
```

**现状**：平台内置「扫一扫」（相机 + BarcodeDetector 识别，自动解析 `RC:编号:区块` 格式）+ 手动输入兜底；凭证页提供"扫码串"一键复制。沙箱环境无法联网生成真码图片，故真码由用户用任意二维码工具生成（10 秒完成），生成后全链路可真实扫码闭环。

## 2. 商业闭环（一张图）

```
馆方/文保单位付费(登记/存证/建档服务)
      ↓
平台沉淀数字资产与凭证
      ↓
① 授权分账(文创/展览/教育使用费，平台抽成)
② 凭证增值(打印/下载/数据导出)
③ 公众扫码验证(免费，但带来流量与信任背书)
      ↓
馆方续费 SaaS + 新馆转化(扫码页=获客入口)
      ↓
闭环：付费 → 资产 → 收入 → 复购/转介绍
```

## 3. 本地一条龙部署（3 种形态）

| 形态 | 方法 | 适用 |
| --- | --- | --- |
| 网页版 | 双击 HTML | 演示、评审 |
| **手机 APP（PWA）** | 双击 `启动APP.bat` → 手机与电脑连同一 WiFi → 手机浏览器打开 `http://电脑IP:8080/区块链平台.html` → 浏览器菜单「添加到主屏幕」→ 桌面图标即 APP（全屏、离线缓存） | 现场路演、试点 |
| 原生 APK | 见第 5 节（HBuilderX 等工具 10 分钟打包） | 正式交付馆方 |

**PWA 三件套已就位**：`manifest.webmanifest`（应用清单）+ `sw.js`（离线缓存）+ `icon-192/512.png`（图标）。注意：PWA 需经 http:// 访问生效，`启动APP.bat` 一键完成（需装 Python）。

## 4. 扫码验证闭环操作步骤

1. 平台「验证」页选文物 → 复制"凭证扫码串"（如 `RC:碧水寺-001:1`）；
2. 用草料二维码/微信小程序把扫码串生成二维码 → 打印贴在文物展签/凭证上；
3. 游客打开 APP「扫一扫」→ 对准二维码 → 自动显示：✅ 链上核验通过 + 文物详情 + 区块号 + 指纹；
4. 假码/未登记码 → ❌ 未找到该凭证（防伪生效）。

## 5. APK 打包步骤（正式交付用）

1. 下载 HBuilderX（免费）→ 新建 5+App 项目 → 选择"WAP2APP"；
2. 应用地址填 `http://服务器地址/区块链平台.html`；
3. 权限勾选：摄像头（扫码必需）；
4. 图标用 `icon-192.png`，包名如 `com.relicchain.app`；
5. 云打包 → 生成 APK → 安装即用。
（替代方案：Cordova / Capacitor 同思路；iOS 需苹果开发者账号签名。）

## 6. 小程序路径（可选）

- 平台页面已按小程序 UI 规范设计（底部导航、移动端适配）；
- 上线需：企业主体 + 小程序备案 + 类目资质（工具-信息查询类）；
- 摄像头扫码 API（wx.scanCode）比网页版更稳，是长期形态。

## 7. 常见问题

**Q：扫一扫黑屏？** A：相机权限未开（浏览器询问时点允许）；不支持 BarcodeDetector 的浏览器请用手动输入。
**Q：双击 HTML 能扫码吗？** A：Chrome/Edge 桌面与安卓版通常支持相机扫码；不支持时手动输入闭环不受影响。
**Q：为什么真码要自己生成？** A：演示环境无网络；任何二维码工具 10 秒生成一次，流程已在第 4 节固化。
