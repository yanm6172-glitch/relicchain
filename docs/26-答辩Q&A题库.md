# 26 答辩 Q&A 题库（比赛评委 × 投资人 40 问）

> 用法：答辩前每人过一遍，回答控制在 30 秒内、先说结论再说依据。

## 一、技术类（15 问）

| # | 问题 | 答题要点 |
| --- | --- | --- |
| 1 | 这是真区块链还是模拟？ | 真算法：SHA-256 真实计算、工作量证明真实挖矿（难度可调）、链式哈希校验、数据持久化；联盟共识为 4 节点模拟展示，生产对接真联盟链（docs/02/04） |
| 2 | 数据存在哪？ | 本机浏览器 localStorage，离线可用、不上传服务器；可全量备份/恢复、导出 JSON |
| 3 | 为什么不用公链？ | 文物数据涉及国家文化资源与数据主权，联盟链境内合规可控；公链成本与数据出境风险不可接受 |
| 4 | 篡改真的防得住吗？ | 哈希链接：改 1 字节指纹全变，逐块校验立刻定位；共识：4 节点多数不一致即被识破 |
| 5 | 上链的是文件本体吗？ | 不是，只上哈希指纹与关键事实（链上最小化原则），文件本体链下存储、分级管理 |
| 6 | 源头数据造假怎么办？ | 链解决"篡改"不解决"造假"：权威机构签名 + 拍照取证指纹 + 流程约束，源头真实性靠背书与审计 |
| 7 | 性能扛得住吗？ | 文物场景是低频高价值写入（TPS<10），联盟链轻松满足；瓶颈在采集与存储，不在链 |
| 8 | 数据丢了怎么办？ | 全量备份一键导出、导入恢复；正式版对接链后全网多节点天然冗余 |
| 9 | 安全吗？ | 本机计算、无服务器攻击面；账号权限分层；正式版加 KMS/HSM、多签、等保 |
| 10 | 为什么 SHA-256 不用国密？ | 演示用 SHA-256 便于公众复验；生产版按 docs/02 双记录 SM3+SHA-256 |
| 11 | 和蚂蚁链/至信链什么关系？ | 定位互补：它们是基础设施，我们是垂直文物的应用层；未来可对接其开放联盟链 |
| 12 | 换链容易吗？ | 架构预留链适配层（docs/04），业务层只依赖统一接口，换链不动上层 |
| 13 | 浏览器算哈希可信吗？ | 本地计算避免中间人；任何人可离线复算比对，无需信任平台 |
| 14 | 开源吗？ | 演示版单文件可读源码；核心算法透明是加分项，商业化部分可选择性开源 |
| 15 | 拍照取证怎么防"拍的是假的"？ | 指纹只证明"此照片即登记时那张"；现场拍摄由机构操作员完成并签名，防的是事后替换 |
