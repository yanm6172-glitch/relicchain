# 28 真实部署说明（服务端版 · v2.0）

> 从"演示文件"升级为"真实软件"：有服务端、有磁盘数据库、多设备数据共享、服务端鉴权。零依赖，仅需 Node.js。

## 1. 架构（真实软件形态）

```
手机/电脑浏览器（区块链平台.html，联网模式）
        │  HTTP（REST API）
        ▼
Node.js 服务端 server.js
  ├── 静态文件服务（本文件夹全部页面）
  ├── REST API（登录/登记/溯源/授权/核验/机构/账号/备份恢复）
  ├── 服务端挖矿（真实 SHA-256 工作量证明）
  └── 数据持久化 → data.json（磁盘，重启不丢）
```

## 2. 启动（30 秒）

1. 安装 Node.js（https://nodejs.org，LTS 版，装一次即可）；
2. 双击 `启动服务器.bat` → 浏览器自动打开 http://localhost:8080/index.html；
3. 手机连同一 WiFi，浏览器打开 `http://电脑IP:8080`（bat 窗口会提示）。

**从此：任何设备登记的数据，所有设备立即可见——这是与离线版最本质的区别。**

## 3. 真实与演示的边界（诚实声明）

| 项 | 现在（真实） | 说明 |
| --- | --- | --- |
| 服务端 | ✅ Node.js HTTP 服务 | 真实网络服务 |
| 数据库 | ✅ data.json 磁盘持久化 | 重启不丢；生产可换 SQLite/MySQL |
| 多设备共享 | ✅ 所有客户端读写同一份数据 | 联网模式自动启用 |
| 账号鉴权 | ✅ 服务端校验 + 密码加盐哈希 | 演示级强度，生产升级 bcrypt |
| 挖矿 | ✅ 服务端真实 SHA-256 PoW | 与演示页同一算法 |
| 备份/恢复 | ✅ 服务端全量导出/导入 | 含链/文物/机构/审计/账号 |
| 联盟共识 | ⚠ 4 节点为展示模拟 | 生产对接 FISCO BCOS（docs/02/04） |
| 加密传输 | ⚠ HTTP 明文 | 生产升级 HTTPS/WSS |

## 4. API 一览（供二次开发）

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/state | 全量状态（链/文物/机构/审计/账号） |
| POST | /api/login | 登录（账号密码，返回会话令牌） |
| POST | /api/block | 上链（服务端挖矿） |
| POST | /api/artifact | 登记文物入库 |
| POST | /api/audit | 写审计日志 |
| POST | /api/verify | 批量文件指纹核验 |
| POST | /api/orgs · /api/org-toggle | 机构准入/启停 |
| POST | /api/accounts · /api/account-del | 账号管理 |
| GET | /api/backup · POST /api/restore | 备份/恢复 |
| POST | /api/reset | 恢复出厂 |

## 5. 生产升级路线（卖给馆方前）

1. 数据库：data.json → SQLite/MySQL（Node 加依赖即可）；
2. 鉴权：SHA-256 加盐 → bcrypt + 令牌过期；
3. 传输：HTTPS 证书；
4. 链：对接 FISCO BCOS/长安链（链适配层已预留，docs/04）；
5. 运维：进程守护（pm2）、每日自动备份 data.json。

## 6. 常见问题

**Q：双击 HTML 和启动服务器的区别？**
A：双击 = 本机演示模式（数据在浏览器里）；启动服务器 = 真实模式（数据在服务端，多设备共享）。平台页顶部会显示当前模式。

**Q：data.json 在哪？**
A：与 server.js 同目录，首次启动自动生成。备份它 = 备份整个平台。

**Q：换电脑迁移？**
A：拷贝整个文件夹（含 data.json）到新电脑，启动即可。

**Q：没有 Node.js 的客户怎么用？**
A：两种：① 帮客户装 Node（一行命令）② 按 docs/18 打包 APK 后接我们的服务端地址。
