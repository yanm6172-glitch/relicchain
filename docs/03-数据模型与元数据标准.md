# 03 数据模型与元数据标准

> 文档定位：回答"一个数字孪生长什么样、一条溯源事件怎么记、文件怎么分级"。

## 1. 参考标准

| 类别 | 标准/规范 | 用途 |
| --- | --- | --- |
| 国际 | CIDOC-CRM | 文化遗产信息参考模型（实体与关系） |
| 国际 | Dublin Core | 通用元数据（标题、创建者、时间等） |
| 国际 | VRA Core | 视觉资源编目 |
| 国际 | IIIF | 图像资源互操作协议 |
| 国内 | WW/T 系列文物藏品元数据规范 | 馆藏文物元数据字段 |
| 国内 | 第一次全国可移动文物普查数据规范 | 普查字段与取值 |
| 技术 | W3C DID Core | 去中心化身份 |
| 技术 | W3C Verifiable Credentials | 可验证凭证 |
| 技术 | JSON-LD / Schema.org | 数据语义化表达 |

**策略**：核心字段对齐国内文物元数据规范；技术表达采用 JSON-LD；身份与凭证采用 W3C 标准，保证未来互操作。

## 2. 实体模型

| 实体 | 说明 | 关键属性 |
| --- | --- | --- |
| Relic | 实物文物 | relicId（馆藏编号）、name、category、period、material、level |
| Twin | 数字孪生 | twinId、relicId、orgDID、currentVersion、status |
| Version | 时点快照 | versionId、twinId、filesMerkleRoot、producedAt、producedBy |
| AssetFile | 数字文件 | fileId、versionId、filename、size、sha256、sm3、grade(L0-L3) |
| Event | 溯源事件 | eventId、twinId、type、payloadHash、evidenceCID、signerDID |
| License | 授权 | licenseId、twinId/versionId、grantee、scope、validFrom/To |
| Org/Person | 机构/个人 | did、name、role、pubKeys |
| Credential | 可验证凭证 | credentialId、issuerDID、subjectDID、claims、proof |

## 3. 孪生元数据 Schema（要点，JSON）

```json
{
  "twinId": "urn:relic-chain:twin:{uuid}",
  "relicId": "馆藏编号",
  "name": "文物名称",
  "category": "类别（按普查分类）",
  "period": "年代",
  "material": "材质",
  "dimensions": { "height": 0, "width": 0, "depth": 0, "weight": 0 },
  "level": "文物等级",
  "orgDID": "did:relic:{馆藏单位}",
  "currentVersionHash": "0x...",
  "status": "REGISTERED",
  "registeredAt": "ISO8601"
}
```

## 4. 状态机

```
DRAFT ──提交审核──▶ PENDING_REVIEW ──通过──▶ REGISTERED
   │                                           │
   │                                     ┌─────┼──────────┐
   │                                     ▼     ▼          ▼
   │                                ON_LOAN  SEALED   REPAIRING
   │                                     │     │          │
   │                                     │     │          ▼
   │                                     │     │      UPDATED（登记新版本）
   │                                     │     │
   └─────────────────────────────────────┴─────┴──▶ ARCHIVED / RETIRED
```

规则：状态变更必须经授权机构签名；历史版本永不删除。

## 5. 溯源事件类型

| 类型 | 说明 | 必填字段 |
| --- | --- | --- |
| COLLECTED | 数字化采集 | 方法、设备、操作人 |
| APPRAISED | 鉴定 | 鉴定结论、报告哈希 |
| EXAMINED | 检测 | 检测项目、报告哈希 |
| RESTORED | 修复 | 修复内容、前后版本哈希 |
| LOANED_OUT / RETURNED | 借展出/归还 | 借展单位、期限 |
| PUBLISHED | 出版/发表 | 出版物信息 |
| LICENSED | 授权 | 授权合约编号 |
| VERSION_UPDATED | 版本更新 | 新旧版本哈希 |
| RETIRED | 注销/灭失 | 原因、依据文件 |

## 6. 事件结构示例（JSON-LD）

```json
{
  "@context": ["https://www.w3.org/2018/credentials/v1"],
  "type": ["Event", "RESTORED"],
  "twinId": "urn:relic-chain:twin:xxx",
  "performedBy": "did:relic:restoration-lab-01",
  "at": "2025-01-15T10:00:00+08:00",
  "evidenceCID": "Qm...（修复报告哈希）",
  "payloadHash": "0x...",
  "proof": { "type": "SM2Signature", "signatureValue": "..." }
}
```

## 7. 可验证凭证示例（检测报告）

```json
{
  "type": ["VerifiableCredential", "ExaminationReport"],
  "issuer": "did:relic:exam-center-01",
  "credentialSubject": {
    "twinId": "urn:relic-chain:twin:xxx",
    "items": ["材质分析", "病害检测"],
    "conclusion": "..."
  },
  "proof": { "type": "SM2Signature", "signatureValue": "..." }
}
```

## 8. 文件分级与哈希

| 级别 | 内容 | 访问对象 |
| --- | --- | --- |
| L0 | 原始采集数据 | 仅馆藏单位/授权修复机构 |
| L1 | 完整高精度模型 | 授权机构（研究、修复） |
| L2 | 展示级模型 | 公众（降精度、带标识） |
| L3 | 缩略图/预览 | 公开 |

- 每个文件记录 SM3 与 SHA-256 双哈希；
- 一个版本的所有文件构成目录 Merkle 树，仅根哈希上链。

## 9. 标识规则

- twinId：`urn:relic-chain:twin:{uuid}`，全局唯一；
- 链下维护"馆藏编号 ↔ twinId"索引，便于检索；
- DID：`did:relic:{机构代码}`，遵循 W3C DID 语法。
