30 秒看懂：文物经扫描采集变成数字孪生（①数据层）→ 只把文件指纹（哈希）写到区块链（②信任层）→ 机构签名写入登记/溯源/授权，公众只读验证（③应用层）。文件本体在链下，链上只有不可篡改的"指纹 + 事实"。

五层架构 点击每一层查看职责说明

关键设计：业务层通过链适配层访问区块链——未来换链（如切长安链）、跨链锚定都不影响上层；链上只存哈希，大文件在对象存储。
应用层
管理后台公众查询端数字展厅开放 API
馆方在管理后台登记与维护；公众在查询端浏览、验证、看溯源时间线；数字展厅承载 L2/L3 展示级内容；开放 API 供第三方与研究机构接入。
服务层
孪生管理登记溯源授权审计DID文件服务
业务逻辑所在：文件哈希计算、交易构建与签名编排、工作流审批、对外接口。写入类接口必须机构签名，查询类接口只读。
链适配层
统一接口：登记 / 查询 / 事件 / 订阅隔离具体链实现
业务层只依赖统一接口，不感知底层是哪条链。这是"可演进"原则的落点：换链、升级链版本、跨链锚定都不牵动上层。
链与数据层
联盟链 FISCO BCOS（PBFT · 国密）MinIO 对象存储PostgreSQL图库搜索引擎
链上只存哈希与状态；对象存储存 L0–L3 分级加密文件；关系库存业务数据；图库存溯源关系（文物-事件-机构网络）；搜索引擎支撑元数据全文检索。
采集层（线下）
三维扫描摄影测量光谱检测修复记录
L0/L1 原始数据的源头，复用馆方现有设备与流程，平台提供采集规范与工具，保证源头质量——这是链上数据可信的第一道关。

溯源事件类型

事件含义
COLLECTED数字化采集
APPRAISED / EXAMINED鉴定 / 检测
RESTORED修复（含前后版本哈希）
LOANED_OUT / RETURNED借展出 / 归还
PUBLISHED / LICENSED出版 / 授权
VERSION_UPDATED / RETIRED版本更新 / 注销灭失

MVP（M1）范围

✔ 包含

  • 联盟链 4 节点（主管部门/试点馆/公证/平台方）
  • TwinRegistry + ProvenanceLog 合约
  • 管理后台：登记、状态、事件录入

  • 数字藏品发行
  • 完整 DID/VC 体系
  • 图库检索、开放 API
  • 跨链司法锚定
